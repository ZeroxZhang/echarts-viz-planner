# 组合叙事规范

> 什么时候读本文档：需要多图组合、看板、汇报叙事时（单图讲得清就不组合）。
> api 模式默认收敛为 1 主 + 至多 1 辅，除非上游传 `composition: true` 或 `max_components > 2`。

## 1. 叙事骨架（模块按此顺序组织）

```
结论 → 发生了什么 → 谁贡献最大 → 为什么 → 证据明细 → 下一步
```

不是每个故事都需要全部六段：单段能完成的故事就不加戏。骨架是检查清单，不是模板强制。

## 2. 模块类型与分工

| 模块 | 用途 | 互斥规则 |
|---|---|---|
| 结论句 | 一句话给出答案 | 必须与图表结论一致，不重复渲染 |
| KPI 卡（≤ 5） | 头部指标 | 与图表数值同口径同版本 |
| ECharts 图 | 模式识别 | 一个模块只回答一个问题 |
| 信息图 | 流程与机制 | 不用于数值表达 |
| 数据表格 | 精确查数 | 图表讲不清的精确值放这里 |
| 原始证据 | 口径与来源 | 支撑可追溯性 |
| 注释 | 口径披露、风险 | 承接 risks/assumptions |

**分工铁律**：模式识别用图表；精确查数用表格；流程与机制用信息图。三者不互相替代、不重复表达同一信息。

## 3. 约束

- 默认 1 主 + 1~3 辅；普通结果 ≤ 4 个主模块。
- 一个模块只回答一个问题；模块顺序 = 叙事顺序。
- 单图讲得清就不组合。
- 看板可增加模块，但必须有层级（分组/页签），不能平铺。

## 4. 常用范式

### 4.1 经营概览
结论句 → KPI 卡（收入/成本/利润/人数 ≤5）→ 主图：趋势（line.multi，收入与成本双线）→ 辅图：构成（bar.pct，收入结构）→ 表格：Top-N 明细。

### 4.2 问题诊断
结论句 → 主图：漏斗或流向（定位流失环节）→ 辅图：横向排名（定位贡献者）→ 辅图：分布（异常与离散）→ 表格：精确数值 → 注释：口径。

### 4.3 用户研究
结论句 → 分布（画像形态：boxplot/violin/直方图）→ 相关（scatter.quadrant，行为×价值）→ 构成（pie.donut，人群占比）→ 表格：明细。

### 4.4 流程效率
结论句 → 主图：漏斗（sankey 或 funnel，阶段流失）→ 辅图：boxplot 或区间图（时长分布）→ 信息图：流程机制 → 注释：数据口径。

### 4.5 高管汇报
结论句（每页一条）→ KPI 卡 → 主图：达成度（gauge.bullet 或 bar.diverging）→ 辅图：趋势 → 备选淘汰从简，风险放注释。

## 5. 汇报型输出原则（scenario: executive / broadcast）

- 每屏一个结论；读者 10 秒内应能说出这张图在讲什么。
- 强调色只有一个；主序列强调，其余弱化（灰度）。
- 图内直接标注结论文字（markPoint / graphic），不依赖读者自己推导。
- 砍掉探索型组件（brush、多级 dataZoom 默认收起）。

## 6. 探索型输出原则（scenario: exploration）

- 交互优先：dataZoom、brush、legend 选择、tooltip 全开。
- 允许信息密度更高（散点矩阵、parallel、多序列）。
- 不追求单图讲清，追求「发现异常的路是通的」。
